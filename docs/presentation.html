Kova

An open-source ride-hailing platform you can run yourself: a rider app, a driver app and an admin console in one Next.js codebase.

MIT licence Next.js 16 Socket.IO MongoDB Redis + H3 Stripe, optional

The problem

Three apps in real time, and money at the end

1

Match in seconds

Find a free, approved driver of the right class near the pickup, and get exactly one of them to say yes.

2

Show the car moving

Stream the driver's position to the rider and keep both apps in step when a phone drops its connection.

3

Settle the money

Charge the rider, credit the driver, keep a ledger that explains every balance, and pay drivers out.

On top of that, many map platforms need a paid API key before the first trip.

The solution

One codebase, one server process, no paid map APIs

R

Rider app

  • Upfront fares for 4 vehicle tiers
  • Live driver tracking and chat
  • 4-digit PIN at pickup
  • Wallet, receipts and ratings
D

Driver app

  • Go online with vehicle details
  • 15-second ride offers
  • Arrive, start with PIN, complete
  • Earnings and Stripe payouts
A

Admin console

  • KPIs and a live fleet map
  • Approve or suspend drivers
  • Pricing rules per tier
  • Contact-form support inbox

How it works

One process serves pages, API and sockets

MongoDB keeps what must last. Redis keeps what changes every few seconds and can be rebuilt after a restart.

How it works

Each step is an API call the server checks

1

Estimate

OSRM route, fares for all 4 tiers, surge from demand and supply

2

Book

One live ride per rider; the wallet must cover the fare; a PIN is drawn

3

Dispatch

Offer to the best driver for 15 s, then the next, up to 8

4

Accept

Atomic claim of driver and ride; the rider sees car and ETA

5

Pickup

Driver marks arrival, then starts only with the rider's PIN

6

Complete

Rider debited, driver credited, ledger rows and a payment record

7

Rate

Each side rates once; averages update

Sockets only tell the other side what already happened. A repeated or late request gets a 409, and a reconnecting app resumes from GET /api/rides/active.

Finding a driver

Search ring by ring, offer one driver at a time

  1. Look in the pickup's H3 cell and the rings around it, read straight from Redis sets.
  2. Widen ring by ring until at least 3 drivers turn up, up to 10 rings for the 15 km radius. MongoDB $geoNear is the fallback.
  3. Score each one: distance 40, rating 25, acceptance 20, few cancellations 15.
  4. Offer to the best driver for 15 seconds. A Redis key names the only driver who may accept.

Status

The full ride loop runs today; several gaps remain

Built in this code

  • Booking, dispatch, live tracking, chat, PIN start
  • Wallet with ledger, late-cancel fee, ratings
  • Stripe top-ups and driver payouts, when configured
  • Admin KPIs, fleet map, approvals, pricing, inbox
  • Health check, Docker image, seed, driver simulator

Not yet built

  • Automated tests
  • Password change or reset, email verification
  • Admin tools to deactivate or delete users
  • Driver document uploads
  • Per-city fares, and running more than one instance

Next steps

Suggested from the gaps in the code and the README

  1. Tests around ride transitions, settlement, top-ups and payouts.
  2. Account management: password change and reset, deactivate and delete users from the admin console.
  3. Driver documents through the presigned upload endpoint that already exists.
  4. Scale out: Socket.IO Redis adapter, a Redis-backed offer queue, self-hosted OSRM and Photon.
  5. Before real passengers: licensing, insurance, money-transmission and driver-classification checks.
